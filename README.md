# HR Gacha — слотмашина кандидатов

3D-слотмашина (React + Three.js / React Three Fiber) для HR: вместо листания резюме крутишь барабаны с ключевыми навыками. Совпали 3+ навыка одного человека на линии — выпадает кандидат.

Игра крутится **по заранее собранной базе** (`public/data/candidates.json`): никаких запросов к внешним API во время игры, мгновенный старт, фильтры по навыкам.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # юнит-тесты: выпадение, нормализация навыков, конвертеры источников
npm run build      # прод-сборка в dist/ (база копируется вместе со статикой)
```

## База кандидатов

```
 JSON Resume Registry ─┐                         ┌─ data/raw/jsonresume.json ─┐
                       ├─ npm run db:jsonresume ─┤                            ├─ npm run db:build ─→ public/data/candidates.json ─→ игра
 GitHub API ───────────┴─ npm run db:github ─────┴─ data/raw/github.json ─────┘
```

**`data/raw/` и `public/data/candidates.json` в git не коммитятся** (см. `.gitignore`) — это персональные данные людей, и хранить их в истории репозитория бессрочно неправильно. Локально вы собираете базу командами ниже; в CI её собирает и обновляет GitHub Actions (см. «Деплой» ниже), а не ручной коммит.

| Команда | Что делает | Сеть |
|---|---|---|
| `npm run db:jsonresume` | Качает резюме из [registry.jsonresume.org](https://registry.jsonresume.org) в `data/raw/`. Инкрементально: уже скачанные пропускает (перекачивает через 30 дней), сам чистит снимки старше 180 дней и тех, кто в `data/removed.json`. | да |
| `npm run db:github` | Ищет разработчиков на GitHub по набору запросов и качает профили+репозитории. Нужен `GITHUB_TOKEN` в `.env.local`. | да |
| `npm run db:build` | Собирает `candidates.json` из сырых данных: нормализует навыки, чистит шаблоны и дубликаты, исключает `data/removed.json`. | нет |
| `npm run db:update` | Всё вместе. | да |
| `npm run db:remove -- <username>` | Право на забвение: заносит юзернейм в `data/removed.json`, стирает его сырой снимок и пересобирает базу. `--source=github` для GitHub-профиля. | нет |

Полезные флаги:

- `npm run db:jsonresume -- --limit=200` — скачать не больше 200 новых резюме (для пробы).
- `npm run db:jsonresume -- --relist` — заново получить список резюме из реестра (по умолчанию кэшируется на 7 дней в `data/raw/jsonresume-usernames.json`).
- `npm run db:github -- --query="language:go location:berlin" --pages=3` — свой поисковый запрос.
- `npm run db:build -- --report` — показать частые **нераспознанные** навыки. Это подсказка, какие алиасы добавить в словарь `src/game/skills.ts`; после правки словаря достаточно `db:build`, без повторной загрузки.

### Про источники

**JSON Resume** — основной. Люди сами публикуют резюме в стандартном формате, навыки указаны явно (`skills[].keywords`), есть должность, город, опыт работы, ссылки (LinkedIn и т.п.). Кнопка «Открыть резюме» ведёт на красиво свёрстанную страницу `registry.jsonresume.org/{username}`.

- Резюме по одному: `GET /api/{username}.json` (документировано, без авторизации).
- Список всех: документированного эндпоинта нет. Сборщик пробует недокументированный `/api/resumes?limit=&page=`, а если он лежит — парсит страницы `/explore`. Если недоступно и то и другое, используется последний сохранённый список.
- В базу попадают резюме с 3+ распознанными навыками; шаблонные («John Doe», «Richard Hendriks»…) и копии отбрасываются. Примерно треть резюме в реестре — не IT (дизайнеры, исследователи) или пустые.

**GitHub** — дополнительный. Навыки выводятся из языков репозиториев (с весом по звёздам), topics и bio. Если один человек есть в обоих источниках, остаётся резюме, а GitHub добавляется ссылкой.

### Данные и приватность

- Источник — публичные профили [JSON Resume Registry](https://jsonresume.org/registry/): люди сами публикуют резюме в открытом формате. Профили остаются собственностью авторов, в каждой карточке есть ссылка на исходное резюме.
- Мы не продаём и не передаём персональные данные третьим лицам. То же самое написано в игре — ссылка «Данные и приватность» в углу экрана.
- База не хранится бессрочно: сырые снимки старше 180 дней (`PURGE_AFTER` в `scripts/lib.ts`) удаляются из кэша сами при каждом запуске `db:jsonresume`, а `public/data/candidates.json` не лежит в git — его пересобирает CI по расписанию из текущего состояния реестра.
- Запрос на удаление — `npm run db:remove -- <username>` (см. таблицу выше): человек больше никогда не попадёт в базу, даже если он всё ещё в реестре.

## Деплой (GitHub Pages)

`.github/workflows/deploy.yml`: по понедельникам и при пуше в `main` — качает свежие резюме (сырой кэш живёт только в Actions cache, не в репозитории), собирает `candidates.json` и прод-бандл, публикует на GitHub Pages через `actions/deploy-pages` (без ветки `gh-pages` и её истории — старые версии базы нигде не накапливаются). Разово в репозитории: **Settings → Pages → Source = GitHub Actions**.

## Как играть

- **Управление — на корпусе машины**, как у игрового автомата: табло сообщений и табло «Линии / Ставка» под окном, на панели — клавиша «Авто запуск», клавиши-пресеты линий 1 · 4 · 9 · 15 · 25, круглые кнопки − / + и большая красная кнопка запуска. Ещё запускают рычаг и пробел, линии меняют клавиши `+` / `−`. На экране поверх 3D — только верхняя полоса (кредиты, шорт-лист, настройки).
- **Выпал кандидат** — карточка сама не открывается: на табло написано, кто выпал, рядом мигает кнопка «Открыть» (или Enter). Если не открывать и нажать запуск, кандидат автоматически обменивается на кредиты. Линии и клетки выигрыша остаются подсвеченными до следующего запуска.
- **Анимации слотов.** Каждому навыку позиции при выборе «кого ищем» раздаётся своя анимация (`src/game/fx.ts`): выпрыгивание, желе, прыжок, блик, волна, искры, качание, пульс; раздача детерминирована по позиции, повторы допустимы. Видно в подсказке к навыку в настройках. Поверх — эффекты по силе выигрыша: ×3 — «змейка» (слоты загораются по очереди с растущей нотой), остальные плитки уходят на второй план; ×4 — бегущая рамка цвета линии; ×5+ — переворот слотов по очереди, конфетти и толчок камеры. После решения по кандидату анимации затихают до мягкого свечения. Выключаются галочкой «Анимации слотов» (по умолчанию выключены при системном «уменьшить движение»).
- **Автозапуск** крутит сам, пока не выпадет кандидат или не кончатся кредиты; повторное нажатие останавливает.
- Ставка 20 кредитов **за каждую линию**, старт — 200.
- **⚙ Настройки → «Нужные навыки»**: после выбора позиции показываются 20 самых частых навыков её кандидатов (с числом людей). Выбираете 3–10 — совпадения считаются **только по выбранным**, остальные символы на барабанах — «пустышки».
- **Линии** — 25 классических линий выплат (1–3 — ряды, дальше V, зигзаги, «крышки», X). Включаются строго по порядку: 1, 2, 3… По краям окна — таблички с номерами активных линий. Сами линии видны ~2 с после смены их числа, при наведении на табличку и при выигрыше (только линии выигравшего комбо); в остальное время барабаны не перекрыты.
- **Совпадение** — сеть линий, связанных пересечениями **в клетках с совпавшими навыками** (цепочка любой длины: A×B, B×C). Пересечение в клетке с невыбранным навыком не связывает линии; линия без своих навыков («мостик») в сеть не входит; порядок навыков на линии не важен. Навыки сети складываются, повторы считаются один раз. Линии 1–3 не пересекаются — это отдельные совпадения: одинаковые 5 навыков на трёх рядах = один человек. Реализация — `evaluateStructure`/`networksFor` в `src/game/outcome.ts`.
- **Минимум линий** подбирается автоматически: до 5 навыков — 1 линия; 6–10 навыков — 4 линии (линия 4 связывает все три ряда в одно комбо на 15 клеток).
- Выигрыш — 3+ выбранных навыка кандидата в одной сети линий. **За спин может выпасть несколько человек**: линии каждого совпадения «забираются», следующее ищется на оставшихся — каждая линия даёт шанс на ещё одного человека (5 навыков: ≈0,1 человека за спин на 1 линии, ≈1,2 на 9, ≈3,5 на 25).
- Выплата за человека = 20 × множитель (×3 → 2,5, ×4 → 5, ×5 → 10, … ×10 → 26) × масштаб. Масштаб калибруется симуляцией под навыки, пул и число линий (в Web Worker), чтобы отдача была ≈0,95: редкие навыки платят больше, на многих линиях каждый человек стоит дешевле.
- Выпавшего можно **открыть** (резюме/профиль), **в шорт-лист** или **обменять на кредиты**. После этого он больше не выпадает.
- **⚙ Настройки → «Кого ищем»**: фильтр через запятую, условия объединяются через И. Навыки распознаются по словарю (`react, docker`), остальное ищется в должности, городе и описании (`senior`, `berlin`). Сразу видно, сколько кандидатов подходит.
- Шорт-лист выгружается в CSV (открывается в Excel).
- Если база не собрана, игра работает на встроенных демо-кандидатах.

## Логика выпадения (`src/game/outcome.ts`)

- **Честные барабаны, без подкрутки.** Каждая из 15 клеток выпадает независимо (`buildReelModel`/`drawGrid`): с вероятностью `targetShareFor(n)` — выбранный навык (3 навыка → 40 %, 5 → 30 %, 10 → 25 %), иначе — «пустышка» (невыбранный навык позиции).
- Вес выбранного навыка ∝ √(доля кандидатов пула с ним): React у 40 % базы выпадает заметно чаще редких навыков, но не забивает поле.
- **Пул — все кандидаты под фильтром**, колоды больше нет. Кандидаты группируются по набору выбранных навыков (`groupBySkills`), поле оценивается по группам; среди равных побеждает случайный человек. Уже выпадавшие (шорт-лист/обмен) не выпадают. На табло вверху: «Пул · Подходят · Выпали».
- `evaluateWins`: жадно берёт самую большую сеть среди всех групп, подсвечивает минимальный связный набор её линий, убирает эти линии и повторяет (до 10 человек). Результат — `SpinResult.wins`, лучший первым.
- Проверить частоты и отдачу: `npx tsx scripts/sim.ts [спинов]`. На реальной базе: 1 линия — выигрыш в ~9 % спинов, 4 — ~40 %, 9+ — ~60–70 %; отдача ≈0,8–1,1 при любом числе линий.

## Структура

```
.github/workflows/  deploy.yml — сборка базы + деплой на GitHub Pages по расписанию
scripts/        сборщики базы: fetch-jsonresume, fetch-github, build-db, remove-candidate, lib
data/raw/       сырые снимки источников (в git не попадают, нужны для db:build без сети)
data/removed.json  юзернеймы, удалённые по запросу (коммитится, кроме них там ничего нет)
public/data/    candidates.json — база, которую грузит игра (в git не попадает)
src/
  game/         types, skills (словарь+нормализация), outcome, economy, bonus, store (zustand), persist
  data/         db (загрузка базы), sources/{jsonresume,github} (конвертеры), mockCandidates, roles
  scene/        Scene, SlotMachine, Reel, BonusBoard, Coins, textures — 3D
  ui/           HUD, WinModal, Shortlist, Settings, Privacy
  audio/        sfx — синтез звуков WebAudio
```
